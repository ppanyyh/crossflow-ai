# CrossFlow AI V4：页面信息架构与状态机

## 1. MVP 页面架构

```text
工作台首页
├── 会话列表
│   └── 会话详情
│       ├── 订单与物流事实卡
│       ├── AI 决策建议卡
│       ├── 英文回复编辑器
│       └── 关联工单入口
├── 工单中心
│   └── 工单详情 / 主管审批
├── AI 质检
└── 运营看板
```

## 2. 页面清单

| 编号 | 页面 | 目标用户 | 核心内容 | 主要交互 |
|---|---|---|---|---|
| P1 | 工作台首页 | 客服 | 待办总览、风险预警、快捷筛选 | 点击状态卡片筛选会话 |
| P2 | 会话列表 | 客服 | 会话摘要、国家、风险、状态、负责人 | 筛选、排序、进入详情 |
| P3 | 会话详情 | 客服 | 原始消息、订单物流事实、处理记录 | 选择处理动作 |
| P4 | AI 决策建议卡 | 客服 | 意图、情绪、规则、风险、建议、草稿 | 采用草稿、编辑、创建工单 |
| P5 | 工单中心 | 客服/主管 | 工单队列、优先级、风险、审批状态 | 进入工单、筛选待审核 |
| P6 | 工单详情与审批 | 主管 | 依据、时间线、建议、审批动作 | 批准、驳回、要求补充材料 |
| P7 | AI 质检 | 客服/运营 | 检查项、结果、修改建议 | 返回编辑、确认通过 |
| P8 | 运营看板 | 运营/主管 | 效率、风险、质量与异常分布 | 切换指标维度 |

## 3. 会话状态机

```text
待处理
 ├── 缺少订单信息 → 待客户补充
 ├── 低风险，回复发送且质检通过 → 已解决
 └── 中高风险 / 低置信度 → 待人工审核

待客户补充
 └── 收到完整订单号 → 待处理

待人工审核
 ├── 主管要求材料 → 处理中
 ├── 主管批准处理建议 → 处理中
 └── 主管驳回 → 待处理

处理中
 ├── 客户回复发送且质检通过 → 已解决
 └── 无法继续处理 / 重复工单 → 已关闭

已解决
 └── 客户再次追问或新证据出现 → 待处理
```

## 4. 工单状态机

```text
草稿（由 AI 建议创建）
  ↓ 客服提交
待人工审核
  ├── 主管要求补充材料 → 处理中
  ├── 主管批准补发建议 → 处理中
  ├── 主管批准退款建议 → 处理中
  └── 主管驳回 → 已关闭 / 返回会话待处理
  ↓
已解决
```

## 5. 高风险主流程的 Axure 页面串联

```text
P1 工作台首页（高风险待办 +1）
  → P2 会话列表（筛选“高风险”）
  → P3 会话详情（CF-DEV-002）
  → P4 AI 决策卡（L-03 + L-06，必须人工）
  → “创建工单”弹窗
  → P5 工单中心（TKT-001：待人工审核）
  → P6 主管审批（批准补发建议）
  → P3 回复编辑（英文草稿）
  → P7 质检通过
  → P3 / P5 更新为已解决
  → P8 看板：人工介入、采纳率、合规率更新
```

## 6. Axure 动态交互清单

| 交互 | 原型实现建议 |
|---|---|
| 风险/状态筛选 | 中继器筛选或动态面板切换 |
| 列表进入详情 | 选中行设置全局变量 `currentCaseId` 后跳转 |
| AI 建议卡随案例变化 | 根据 `currentCaseId` 切换动态面板状态 |
| 创建工单 | 弹窗 + 设置 `ticketCreated=true`、会话状态为待人工审核 |
| 主管审批 | 修改 `ticketStatus` 与 `supervisorDecision` 变量 |
| 回复编辑 | 文本框预填草稿，保存值到全局变量 |
| 质检 | 合规草稿显示通过；含“refund today”等禁用语时显示需修改 |
| 看板联动 | 依据 `ticketStatus`、`replyAdopted`、`qualityPassed` 切换模拟指标 |
